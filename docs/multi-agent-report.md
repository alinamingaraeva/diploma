# Мультиагент vs один агент (ДЗ 6.5)

Дата прогона: 31 августа 2026, ~10:17–10:19 МСК.  
Модель — Polza `openai/gpt-4o-mini`, `temperature=0`.  
Tool в обеих реализациях один: `search_knowledge_base` → RAG `rag_eval_1024` (top-3 чанка со score ≥ 0.38).  
Код только в `experiments/`, в `app/` не переносился. Сырые числа: `experiments/results.json`.

## Сценарий

Посетитель задаёт вопрос консультанту музеев Казанского Кремля (телефон, правила, отказ, если в документах нет).  
**researcher** вызывает `search_knowledge_base` и возвращает маркированный список фактов с источниками, без ответа посетителю.  
**writer** из этих фактов собирает связный русский текст и обязан оставить цитаты `[1]`, `[2]`.  
Ожидаемый финал: короткий ответ с номерами источников; если база пуста — честный отказ без выдуманных телефонов. Тот же вход и тот же формат у single-agent (один `create_agent` с тем же tool).

Сборка: `langgraph_supervisor.create_supervisor` на Polza даёт HTTP 502 «некорректный вызов инструмента» на handoff-tools. Рабочий вариант — ручной граф `Command(goto=...)`: START → researcher → writer → END, `InMemorySaver`, `thread_id` с префиксом `exp-langgraph`. Схема: `docs/architecture-multi-agent.md`.

## Сравнительная таблица (среднее по 5)

| Метрика | Single-agent | Multi-agent | Δ |
|---------|--------------|-------------|---|
| Токены на запрос | 1302.8 | 2305.4 | ×1.77 |
| LLM-вызовов на запрос | 2.0 | 3.0 | +1 |
| Latency p50 (мс) | 4846.4 | 6358.5 | +31% |
| Передач управления на запрос | 0 | 2.0 | +2 |
| Качество (LLM-судья, 0–5) | 5.0 | 5.0 | 0 |
| Качество (эвристика фактов, 0–5) | 5.0 | 4.0 | −1.0 |

LLM-судья ставит 5 и за верные факты, и за «честный отказ». На Q4 мультиагент отказал («в документах нет»), хотя оба факта в корпусе есть и single их нашёл. Эвристика это ловит: нужен телефон `567-80-16` и правила про собаку. Цитаты `[n]` в финале: single 4/4 на корпусных+многошаговом, multi только 1/4 (writer часто снимает номера).

Мультиагент не дал прироста качества. Он дороже по токенам (~×1.8) и медленнее по медиане (~×1.3), плюс две передачи researcher→writer на каждый запрос. На единственном многошаговом вопросе конвейер **хуже** baseline: researcher не собрал оба факта, writer оформил отказ. Цитирование, ради которого заводили writer, в трёх из четырёх корпусных ответов пропало. Для музейного FAQ с общим контекстом и одним RAG-tool разделение ролей не окупается.

## Сопоставление с Anthropic

В «How we built our multi-agent research system» (июнь 2025) multi-agent ≈ **15×** токенов обычного chat и **+90.2%** качества на breadth-first research: много независимых направлений, мало общего контекста. У нас множитель токенов **×1.77** (2305 / 1303), не ×15: нет fan-out по субагентам, только два последовательных вызова. Задача на breadth-first не похожа: один корпус, один tool, один поток фактов, ответ write-heavy (короткий FAQ с цитатами). Anthropic как раз предупреждает, что в доменах с tight coupling и общим контекстом мультиагент проигрывает. Наши числа это подтверждают: стоимость выше, качество не выросло, на Q4 упало.

## Решение

**Не использовать мультиагент в дипломе.** Оставляем один агент с tools (как в 6.3/6.4: `create_agent` / персистентный граф с HIL), без supervisor и без переноса `experiments/` в `app/agents/`.

Музейный консультант — общий контекст и один RAG, не исследование «вширь». Прирост качества нулевой, токены ×1.77, latency +31%, на многошаговом вопросе мультиагент ошибся, а цитаты writer чаще теряет, чем добавляет. Паттерн supervisor / researcher / writer в прод не едет; сравнение остаётся аргументом на защите.
