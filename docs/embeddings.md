# Выбор embedding-модели (ДЗ 5.1)

## Решение

Для корпуса на русском (kazan-kremlin.ru) берём **OpenAI `text-embedding-3-small` через Polza** (`openai/text-embedding-3-small`).

Почему не локальный MiniLM и не `text-embedding-3-large`:

- Язык: 3-small стабильно работает на русских музейных формулировках; ruMTEB-специализированную модель можно сменить позже, не ломая интерфейс `embed_texts`.
- Размерность: **1536** — стандарт ДЗ, меньше индекс, чем у 3-large (3072).
- Стоимость: тот же ключ, что и чат; не нужен отдельный HuggingFace-рантайм на CPU.
- Сеть: батчи по 32 (можно 100–512), retry через tenacity, дисковый кеш `var/embeddings_cache` — повторный текст не идёт в API. Смена `EMBEDDING_MODEL` даёт другой ключ кеша.

Модель не из семейства E5: отдельные префиксы `query:` / `passage:` не требуются. Методы `embed_query` / `embed_documents` есть как обёртки над `embed_texts`.

## Стоимость индексации 50+ документов

Ориентир OpenAI list price `text-embedding-3-small` ≈ **$0.02 за 1M токенов**.

Если 50 страниц музея по ~400 токенов → ~20 000 токенов → **меньше $0.001**. Даже 500 чанков по 500 токенов → 250 000 токенов → **около $0.005**. У Polza смотрите фактический тариф в кабинете; порядок тот же.

Проверка: `python -m scripts.embed_smoke` (нужен ключ). Второй прогон тех же строк должен дать `cache_hit_expected: true` и `api_calls` без роста.

В `data/museum/` — общие страницы (часы, контакты, правила, билеты, маршрут, афиша, экскурсии) и **все музеи/залы комплекса**: Эрмитаж-Казань, естественная история, Пушечный двор, исламская культура, Благовещенский собор (музей), государственность, Спасская башня, Манеж, Присутственные места, плюс мечеть Кул-Шариф. Указатель: `data/museum/index.md`. На 5.2 нарезано на **106** чанков, индекс в Qdrant (см. [vector_store.md](vector_store.md)).
