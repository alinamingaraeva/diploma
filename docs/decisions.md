# Итоговые решения диплома

Документ для итоговой аттестации: по каждому решению — **что выбрано**, **из чего выбирали**, **почему так**. Ответ «так удобнее» здесь не используется.

Тема: ИИ-консультант музеев Казанского Кремля в Telegram.

## Предметная область

**Выбрано.** Музеи-заповедник «Казанский Кремль»: часы, билеты, контакты, правила, экскурсии, площадки комплекса.

**Альтернативы.** Общий «бот про Казань»; интернет-магазин; внутренний HR-FAQ компании.

**Почему.** Есть открытые тексты с kazan-kremlin.ru, понятный пользователь (посетитель), цена ошибки высока (нельзя выдумать телефон и 450 ₽), задача хорошо ложится на RAG, а не на «общие знания» модели.

## Канал: Telegram, а не сайт и не виджет

**Выбрано.** Бот aiogram 3 как тонкий клиент к FastAPI.

**Альтернативы.** Виджет на сайте музея; отдельное веб-приложение; Jivo с оператором.

**Почему.** Курс требует мессенджер; посетитель уже в Telegram по дороге в Кремль; бота можно заменить, история остаётся на сервере (ДЗ 4.2). Сайт музея не отдавали под встраивание.

## Зачем ИИ, а не FAQ-страница

**Выбрано.** RAG + короткие кнопки меню.

**Альтернативы.** Статическая страница «частые вопросы»; поиск по ключевым словам по сайту; живой оператор.

**Почему.** Вопросы формулируют по-разному («куда звонить», «телефон визит-центра»). Ключевые слова не находят абзац без слова «телефон». Оператор дороже учебного контура. ИИ нужен, чтобы связать свободный вопрос с фрагментом документа и отказаться, если фрагмента нет. Кнопки закрывают 4 самых частых сценария без модели.

## Модель генерации

**Выбрано.** Облачный OpenAI-совместимый API Polza, `openai/gpt-4o-mini`.

**Альтернативы.** Локальная Llama на своей видеокарте; Claude / gpt-4o «полный»; прямой api.openai.com.

**Почему.** Учебный ключ уже на Polza; русские короткие FAQ; бюджет единицы долларов в месяц. Локальная 7B–13B на домашнем ПК без выделенной GPU нестабильна и не нужна по нагрузке 30–100 сообщений/час. Anthropic в `.env` нет — в отчётах это сказано прямо, судья RAGAS тоже gpt-4o-mini.

## Эмбеддинги и векторная база

**Выбрано.** `text-embedding-3-small`, размерность 1536, метрика cosine, Qdrant, коллекция `rag_eval_1024`.

**Альтернативы.** Локальный MiniLM; `text-embedding-3-large` (3072); Chroma/FAISS на диске; переиспользовать учебную коллекцию `documents` из ДЗ 5.2.

**Почему.** Русский корпус, тот же ключ, что у чата, нормализованный cosine «из коробки». Large дороже и требует другой индекс. FAISS неудобен как сервис в compose. Коллекция `documents` — плоский payload qdrant-client; LlamaIndex пишет `_node_content` — схемы несовместимы, поэтому боевой индекс отдельный.

## Нарезка документов

**Выбрано.** Fixed chunk **1024**, overlap 64, retrieve 24, в генерацию 5, rerank выключен, score-guard **0.38**.

**Альтернативы.** Chunk 512 (победитель retrieval-эксперимента 5.4); semantic splitter; top_n=10; cross-encoder bge-reranker.

**Почему.** По Hit@5 выигрывал 512, но по RAGAS на 32 вопросах 1024 дал relevancy 0.67→0.75 и citation 0.91→1.00: короткий `tickets.md` целиком в одном чанке, модель видит «450 ₽». top_n=10 ухудшил faithfulness. Reranker на CPU секунды на запрос, MRR не вырос. Порог 0.38 лежит между offtopic (~0.1) и музейными фактами (~0.45–0.70).

## История диалога

**Выбрано.** История на сервере: JSONL локально, Postgres в compose. Sliding window.

**Альтернативы.** Память только в процессе бота; только Redis.

**Почему.** Рестарт бота не должен стирать диалог. JSON — ноутбук без Docker. Postgres — ближе к проду. Redis оставляем для кеша LLM, не как единственное хранилище чата.

## Агентный слой

**Выбрано.** Один агент LangGraph с тремя tools: `search_knowledge_base` (RAG), `get_current_time`, `send_telegram_message` (заглушка print) + human-in-the-loop перед отправкой. Память sqlite/postgres.

**Альтернативы.** Только RAG без агента; мультиагент researcher+writer+supervisor; CrewAI / OpenAI Agents SDK.

**Почему.** Агент нужен, когда модель сама решает вызвать поиск или «отправку». Мультиагент сравнили в `experiments/`: токены ×1.77, на двух фактах сразу — ложный отказ. Anthropic: multi-agent выигрывает на breadth-first research (~15× токенов), у музея общий контекст. Стек LangGraph совместим с checkpoint ДЗ 6.4. Другой фреймворк ломал бы HIL.

## Поведение при сбоях

**Выбрано.** Кнопки меню без LLM; бот отвечает «сервис недоступен», не traceback; Redis опционален; `/health` vs `/ready`; JSON-история если Postgres лёг.

**Альтернативы.** Упасть всем процессом; очередь RabbitMQ; второй облачный ключ как обязательный runtime.

**Почему.** Нагрузка учебная, очередь избыточна. Второй ключ заложен в ADR, в домашнем `.env` его может не быть — деградация до кнопок достаточна. Недоступный RAG на старте не блокирует API.

## Качество

**Выбрано.** Golden 32 пары, RAGAS (faithfulness 0.94, relevancy 0.75, citation 1.00 на chunk 1024), Phoenix для «почему».

**Альтернативы.** «На глаз пять вопросов»; только LLM-as-judge без retrieval-метрик.

**Почему.** Курс требует ≥30 пар и числа, не впечатления. Судья шумный ±5–10% — в failure analysis это разобрано (верный «450 ₽» с faith=0 при recall=1).
